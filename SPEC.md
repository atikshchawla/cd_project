# Interactive Compiler Visualizer — Build Spec (MVP)

> Audience: the coding agent building this project. This single file is the source of truth.
> Build **only** what is in sections 1–12. Section 13 lists deferred work: do NOT build it now.

## 1. Goal

An educational website where a user picks a small C program, compiles it, and explores how it moves through compiler stages:

**Source → Tokens → AST → Semantic Analysis → IR → Assembly → Execution (VM)**

Selecting an item in one stage highlights the related items in the other stages (source, tokens, AST, IR, assembly). Invalid programs show clear diagnostics and explain which stage failed and why later stages are unavailable.

Every stage panel explains: **what is happening**, **what the compiler produces**, **why it matters**, plus an explanation of the currently selected item.

## 2. Non-negotiable rules

1. **Pure Next.js** (App Router, TypeScript strict). One app. No separate backend, no API routes for compiling, no Docker/Python, no child processes, no Clang/LLVM binaries, no WebAssembly toolchains.
2. **Only the npm packages in section 3.** Need another? Stop and ask.
3. **The compiler is our own**: a small educational C-subset ("Mini-C") compiler in TypeScript under `lib/compiler`. Real Clang/LLVM cannot run in a pure Next.js app. Therefore **never** call its output "Clang output" or "real LLVM IR" in the UI or code. Call it "generated by this app's compiler" and "LLVM-style IR".
4. Everything runs **in the browser**. User code is never executed natively.
5. **Cross-stage mapping uses IDs and source ranges only**, never text matching.
6. Build in the milestone order of section 11. Each milestone must end with a working app and passing `npm run build`, `npm run lint`, `npm test`.

## 4. Supported language: Mini-C

| Area | Supported |
|---|---|
| Types | `int` (32-bit), `void` (return position only), pointers (`int *`, `int **`), arrays (`int a[3]`, `int m[2][3]`), `struct` / `union` records with named fields. A field may be a pointer, an array or another record, so nesting works to any depth (`t.m.l.v`), and `struct P a[3]` is an array of records |
| Declarations | local and global variables with an optional initialiser or `{ … }` list; record declarations; functions with ≤ 4 parameters (array parameters decay to pointers) |
| Expressions | integer literals; string literals (only as a `printf` format); identifiers; `+ - * / %`; `< > <= >= == !=`; `&& \|\| !`; unary `- + & *`; `= += -= *= /= %=`; `++ --` (prefix and postfix); indexing `a[i]`; member access `.` / `->`; pointer arithmetic and pointer comparison; `new T` / `new T[n]`; `sizeof(type)` (cell count); function calls; `print(...)` / `printf(...)`; parentheses |
| Statements | block, expression statement, `if/else`, `while`, `for` (init may be a declaration), `return`, `break`, `continue`, empty `;`, `delete ptr;`, `print` / `printf` calls |
| Dynamic memory | `malloc(n)` / `free(p)` and `new` / `delete` over cell-addressed memory; every block carries its own guard cell so a one-past-the-end pointer is never confused with the next variable |
| Preprocessor | `#include <...>` lines are lexed as one `directive` token and ignored |

Everything else (`char` and text as values, floats, `do-while`, `switch`, `goto`, ternary, comma operator, bitwise/shift operators, casts, `const`/`static`/`extern`/`unsigned`, `typedef` / `enum`, variable-length or empty array sizes (`int a[n]`, `int a[]`, `int f(int a[][3])`), hexadecimal literals, function pointers, varargs, passing or returning a record by value, whole-record assignment, non-literal global initialisers, directives other than `#include`, etc.) must produce a clear diagnostic explaining what *is* supported — `E1010` when the construct is recognised but unsupported, a syntax error when the grammar has no production for it. Never crash, and never silently mis-compile (the one tolerated divergence: a leading zero is not octal, so `010` reads as decimal ten).

Grammar (precedence climbing, hand-written recursive descent):
```
translation_unit = { directive | external_decl } ;
external_decl    = type_spec declarator ( "(" [params] ")" ( compound | ";" ) | [ "=" initializer ] ";" ) ;
type_spec        = ("int"|"void") | ("struct"|"union") ident ;
declarator       = "*"* ident { "[" integer "]" } ;
params           = "void" | type_spec declarator { "," type_spec declarator } ;
record_decl      = ("struct"|"union") ident "{" { type_spec declarator ";" } "}" ";" ;
compound         = "{" { declaration | record_decl | statement } "}" ;
declaration      = type_spec declarator [ "=" initializer ] ";" ;
initializer      = assign | "{" [ initializer { "," initializer } [ "," ] ] "}" ;
statement        = compound | if | while | for | "return" [expr] ";" | "break" ";" | "continue" ";" 
                 | "delete" expr ";" | ("print"|"printf") "(" [expr { "," expr }] ")" ";" | [expr] ";" ;
if               = "if" "(" expr ")" statement [ "else" statement ] ;
while            = "while" "(" expr ")" statement ;
for              = "for" "(" ( declaration | [expr] ";" ) [expr] ";" [expr] ")" statement ;
expr             = assign ;
assign           = logical_or [ assign_op assign ] ;         (* lvalue checked in sema *)
logical_or       = logical_and { "||" logical_and } ;
logical_and      = equality { "&&" equality } ;
equality         = relational { ("=="|"!=") relational } ;
relational       = additive { ("<"|">"|"<="|">=") additive } ;
additive         = multiplicative { ("+"|"-") multiplicative } ;
multiplicative   = unary { ("*"|"/"|"%") unary } ;
unary            = ("-"|"+"|"!"|"&"|"*"|"++"|"--") unary
                 | "sizeof" "(" type_spec "*"* ")"
                 | "new" type_spec [ "[" expr "]" ]
                 | postfix ;
postfix          = primary { "(" [args] ")" | "[" expr "]" | "." ident | "->" ident | "++" | "--" } ;
primary          = ident | int_lit | string_lit | "(" expr ")" ;
```

}

## 6. Compiler engine

### 6.1 Lexer
- Normalise `\r\n` / `\r` to `\n` first. Skip whitespace and `//`, `/* */` comments (not tokens).
- Keywords: `int void if else while for return break continue struct union sizeof new delete print printf`. Reserved-but-unsupported words (`char float double long unsigned switch case default goto typedef enum static const do class namespace template`) lex as keywords and yield `E1010` in the parser.
- Operators (longest match): `++ -- += -= *= /= %= == != <= >= && || -> + - * / % < > = ! &`. Punctuators: `( ) { } ; , [ ] .`.
- String literals `"…"` are their own token kind (`string-literal`); escapes are decoded at lex time. An unterminated one is `E1003` and the token is still emitted so the rest of the line stays visible.
- Any other character such as `| ^ ~ ? : @` → `E1010` (unsupported) with an explanation; characters with no meaning at all (control characters, non-ASCII, a `#` that is not at the start of a line) → `E1001`. Unterminated block comment → `E1002`. Integer literal > 2147483647 → `E1004`.
- Never throws; returns tokens (possibly partial) plus diagnostics.

### 6.2 Parser
- Output `Ast` as a flat `nodes` map; IDs in creation order; maintain `parentId`/`childIds`; each node's `range` covers exactly its source text.
- **Stop at the first syntax error**: one diagnostic (`E2001` expected X, `E2002` unexpected token/EOF) with a range at the offending token (or the end of the previous token for "expected `;`"), and return `ast: null`. No recovery.
- Keep `ParenExpr` nodes. No implicit-cast nodes (types are shown as annotations).
- `=` is a `BinaryOperator` with `op:'='`; `+= -= *= /= %=` are `CompoundAssignOperator`; `++/--` are `UnaryOperator` with `op` `'prefix++' | 'postfix++' | 'prefix--' | 'postfix--'`; `&` and `*` are `UnaryOperator` with `op` `'prefix&' | 'prefix*'`.
- Declarations go through a **declarator**: the written type is recorded on the node as `typeRef` (`base`, `tag`, `stars`, `dims`, outermost first) so sema — not the parser — decides what it means. Array sizes must be integer literals ≤ 100000, otherwise `E1010`.
- Records: `struct`/`union` tags followed by `{ … }` become `RecordDecl` with `FieldDecl` children. `new T` / `new T[expr]` become `NewExpr` with `op 'new' | 'new[]'`; `delete expr;` a `DeleteStmt`; `print` / `printf` a `PrintStmt` with `op 'print' | 'printf'`.
- Member access `.` / `->` and subscripts `[ ]` are postfix operators (`MemberExpr`, `ArraySubscriptExpr`). A reserved keyword used as a name is `E1010` with the keyword's own range.

### 6.3 Semantic analysis
Scope-stack walk. Produce `symbols`, `scopes`, `type` on every expression/declaration, `refDeclId` on every `DeclRefExpr`, `useNodeIds`, and diagnostics. **Collect multiple semantic errors** (don't stop at the first). Messages are our own wording in a Clang-like style.

| Code | Severity | Meaning |
|---|---|---|
| E1001 E1002 E1004 | error | lexical: invalid char / unterminated comment / literal too large |
| E1003 | error | lexical: unterminated string literal (the token is still emitted) |
| E1010 | error | unsupported construct — stage `unsupported` from the lexer/parser, stage `sema` when semantic analysis meets a type this dialect cannot lower |
| E2001 E2002 | error | syntax: expected token / unexpected token |
| E3001 | error | use of undeclared identifier (calling an undeclared function included) |
| E3002 | error | redeclaration in the same scope |
| E3003 | error | incompatible types (assigning `void`, a whole record/array, using a `void` call as a value) |
| E3004 | error | wrong number of arguments in a call |
| E3005 | error | no member with that name in the record |
| E3006 | error | `break`/`continue` outside a loop |
| E3009 | error | `return` value mismatch with function type |
| W4001 | warning | unused local variable |
| W4002 | warning | non-void function may end without `return` (not for `main`) |

Also treat assignment to a non-lvalue as `E3003`. A rejected signature must not cascade: when a record parameter or return type is reported as unsupported, the declared type is kept so the body still analyses against what was written. Do not display any semantic fact that wasn't computed.

### 6.4 IR generation — LLVM-style, `-O0`-like
Generate from the **annotated AST**. Style: unoptimised Clang-like output (locals in `alloca`, accessed by `load`/`store`), opaque `ptr`. Types: `i1`, `i32`, `ptr`, `void`. Opcodes: `alloca load store add sub mul sdiv srem icmp zext ptradd ptrdiff br ret call unreachable`. **No `phi`.**

```llvm
define i32 @add(i32 %a, i32 %b) {
entry:
  %a.addr = alloca i32
  %b.addr = alloca i32
  store %a, %a.addr
  store %b, %b.addr
  %0 = load %a.addr
  %1 = load %b.addr
  %add = add %0, %1
  ret %add
}
```

Rules (they prevent invalid IR):
1. **Builder invariant:** every block ends in exactly one terminator. If code is emitted into an already-terminated block (e.g. after `return`), start a new block first. At function end, if the open block is unterminated: `ret void` (void fn), `ret i32 0` (`main`), else `unreachable`. Finally **prune blocks with no predecessors** (except `entry`).
2. Allocas for params and locals go in `entry` (collect while generating, insert at top). Param `x` → `%x.addr`; local `x` → `%x` (numeric suffix when shadowed). Set `varName` on each alloca.
3. Value names: hint names (`%add`, `%cmp`, `%call`, `%inc`) plus numeric temps (`%0`, `%1`…) with a per-function counter; names are unique per function and **never renumbered**.
4. Conditions: `int → i1` via `icmp ne %v, 0`. Comparison results are `i1`; when used as an `int`, `zext … to i32`. `!x` → `icmp eq %x, 0` + `zext`. Unary minus → `sub 0, %x`.
5. `&&` / `||` without `phi`: use a hidden `i32` temp alloca (`%land.tmp` / `%lor.tmp`), blocks `land.rhs`/`land.end` (`lor.rhs`/`lor.end`), store 0/1 on the paths and `load` it in the end block. The explanation text notes real Clang uses `phi` here.
6. Block labels (add a numeric suffix to keep unique): `entry if.then if.else if.end while.cond while.body while.end for.cond for.body for.inc for.end`. `break` → loop end; `continue` → cond (while) or inc (for).
7. `++/--`: load, `add %x, 1` (or `sub`), store; the expression value is the new value (prefix) or old value (postfix). Compound assignment: load, op, store.
8. Calls print `call @f(%0, …)` — with a `%x = ` result only when the callee returns a value, since the types are written once on the `define`/`declare` line. Functions without a body are `declare`d — including the language's own `malloc`, `free`, `delete`, `print` and `printf`, which are appended only when the program uses them. Globals are emitted as `@g = global i32 <init or 0>` (arrays and records add `cells` and a per-cell `inits` list, printed bare as `[n x i32] [0, 7, …]`) and referenced with `ptr @g`.
9. **Provenance:** set `astNodeId` on every instruction to the most specific AST node it was generated for (the `add` → its `BinaryOperator`; loads → the `DeclRefExpr`; allocas → `VarDecl`/`ParamDecl`; branches → the `IfStmt`/loop node). Compiler scaffolding with no honest origin (e.g. the synthetic `ret i32 0`) gets no `astNodeId`.
10. `irprint.ts` is a pure function `IRModule → IRLine[]` with `instrId`/`blockId` per line; it never mutates the module. **Printed form — write only what carries information:** a type appears where it *declares* something the line cannot otherwise show (`define`/`declare` signatures, `alloca` slots, `zext … to i32`, `global` declarations) and is omitted where the line already implies it (a load's type is its result's, a store's is the value it writes, arithmetic is always `i32`). No `align` and no `nsw` are ever printed: every slot is one cell of an already-aligned stack and every operation wraps at 32 bits, so `align 4` would repeat a constant and `nsw` would be a lie. Strings stay quoted with their escapes re-escaped (`"sum=%d\n"`).
11. IR is only generated if there are **no errors** (warnings are fine). Otherwise `ir: null`.
12. **Addresses, not syntax:** `&x`, `+e` and a decay of an array/record name produce no instruction — they only produce the operand that *denotes* an address. `a[i]`, `p.f` and `*p` on an aggregate become `ptradd <base>, <cells>` (constant offsets are folded into the operand, larger strides become a `mul`); `p - q` becomes `ptrdiff`. `*p` on a scalar still loads.
13. **Aggregates:** an array or record is one `alloca` carrying `cells` and a `shape` such as `[5 x i32]`; each element or field is written with a `store` to its computed address, so a member at offset 0 still gets a `ptradd` of 0 and unions share offset 0.
14. **Builtins:** `malloc(n)` is `call @malloc(…)` (with `sizeof` folded into the size), `free`/`delete` are `call @free(…)` / `call @delete(…)`, and `print`/`printf` are `call`s whose format operand is `{ kind: 'string', value: … }`. `new T` becomes a `malloc` of one object's cells, `new T[n]` of `n × cells`.

### 6.5 Shared integer helper (`int32.ts`)
Create it now even though only IR uses it lightly: `wrap32(x) = x | 0`, `mul32 = Math.imul`, truncating division. It is reserved for constant folding and the simulator later; both must import it so they can never disagree.

## 7. Selection model and cross-stage highlighting

### 7.1 Single selection in the Zustand store
```ts
type Origin = 'editor' | 'stage';
type Selection =
  | { kind: 'none' }
  | { kind: 'source'; range: Range; origin: Origin }
  | { kind: 'token'; tokenId: number; origin: Origin }
  | { kind: 'ast'; nodeId: number; origin: Origin }
  | { kind: 'symbol'; symbolId: number; origin: Origin }
  | { kind: 'ir'; instrId: number; origin: Origin }
  | { kind: 'asm'; lineId: number; origin: Origin }
  | { kind: 'diagnostic'; diagnosticId: number; origin: Origin };
```
(Add more kinds later: `irblock`, `sim`.) One selection at a time; it **persists when switching stages**.

### 7.2 `computeHighlights(selection, result): Highlights` (pure, in `lib/highlight.ts`)
```ts
interface Highlights {
  primary: { stage: Stage; id: number } | null;
  sourceRanges: Range[]; tokenIds: Set<number>; astNodeIds: Set<number>;
  symbolIds: Set<number>; irInstrIds: Set<number>;
  unavailable?: string;        // human reason when no reliable mapping exists
}
```
| Selection | Source ranges | Tokens | AST | IR |
|---|---|---|---|---|
| `source` | the range | tokens overlapping it | **innermost** node containing the range, plus ancestors (related) | instrs whose `astNodeId` is in that node's **subtree** |
| `token` | token range | that token | innermost node containing it | via the AST rule |
| `ast` | node range | tokens fully inside the range | node + descendants | instrs with `astNodeId` in the subtree |
| `symbol` | decl range + every use range | identifier tokens of decl/uses | decl node + use nodes | the alloca with that `varName` and its loads/stores |
| `ir` | range of its `astNodeId` | tokens in it | that node | the instr (+ siblings with the same `astNodeId` as related) |
| `diagnostic` | `diag.range` | tokens in it | innermost node (if any) | — |

If there is no `astNodeId` / mapping (e.g. a `define` line, a label, scaffolding), set `unavailable` to a clear sentence such as "This is compiler scaffolding; it doesn't correspond to a source expression." Show it in the explanation panel. **Never guess.** Selecting a diagnostic also switches the active tab to the stage that reported it.

### 7.3 Visual treatment (never colour alone)
- primary: strong background + 2 px outline + bold.
- related: lighter background + dashed outline/underline.
- unrelated: slightly reduced opacity (never below 4.5:1 text contrast).
- In Monaco use `editor.createDecorationsCollection` with CSS classes `hl-primary` / `hl-related`.

### 7.4 Editor ↔ store contract (prevents loops and offset drift)
1. On editor mount: `model.setEOL(monaco.editor.EndOfLineSequence.LF)`. Compile `model.getValue()`.
2. Convert with `model.getOffsetAt(pos)` / `model.getPositionAt(offset)` (Monaco is 1-based).
3. Caret/selection changes → `{ kind:'source', origin:'editor' }`, debounced ~100 ms.
4. The editor only **draws decorations** and reveals ranges (`revealRangeInCenterIfOutsideViewport`) when `origin !== 'editor'`. It **never moves the caret** in response to store changes.
5. **Staleness:** compare `result.sourceHash` with the hash of the current editor text. If they differ: show a "Source changed — recompile" banner, grey the results, return empty `Highlights`, clear markers. Never apply offsets from an old compile to new text.
6. Diagnostics → `monaco.editor.setModelMarkers(model, 'minic', …)`.

## 8. UI specification

**Layout (desktop first):** top bar (title, example picker, **Compile** button, About) → stage navigator + settings strip → two columns: **editor on the left (~40%, always visible)**, **stage workspace on the right**, with the explanation panel docked at the bottom of the workspace. Below ~1024 px simply stack: editor on top, workspace below.

**Settings strip:** `Mini-C compiler v0.1 · IR style: LLVM-like (opaque pointers) · optimisation: none`.

**Provenance badges** (`<ProvenanceBadge kind>`): `generated` (tokens, AST, symbols, diagnostics, IR), `derived` (explanations built from generated data), `illustrative` (hand-written teaching notes, lowered assembly), `simulated` (VM execution states and traces). An About dialog and a one-line banner say: *"This app uses its own educational Mini-C compiler written in TypeScript. Its output resembles Clang/LLVM output but is not produced by Clang or LLVM."*

**Stage navigator:** Source · Lexical Analysis · Syntax Analysis (AST) · Semantic Analysis · Intermediate Representation · Generated Assembly · Execution (VM). Each step shows an icon **and** text status: `ready | ok | warnings | failed | blocked | stale`. Supports normal compilation and a step-through mode where stages advance one at a time.

**Stage status rules (`status.ts`):**
| Situation | lex | parse | sema | ir | asm | sim |
|---|---|---|---|---|---|---|
| Before first compile | ready | ready | ready | ready | ready | ready |
| Lexical error | failed | blocked | blocked | blocked | blocked | blocked |
| Syntax error | ok | failed | blocked | blocked | blocked | blocked |
| Semantic error(s) | ok | ok | failed | blocked | blocked | blocked |
| Warnings only | ok | ok | warnings | ok | ok | ok |
| Clean | ok | ok | ok | ok | ok | ok |
Blocked stages show: "Not available — *<Stage>* reported errors, so the compiler stopped before this stage." with a link selecting the first error. Tokens stay viewable after a parse error; the AST stays viewable (with partial info) after semantic errors.

**Source / editor:** Monaco with C highlighting, line numbers, markers, a Problems bar below it (count + list). Compile via button and `Ctrl/Cmd+Enter`. Example dropdown (section 10) with a **Reset to example** button. States: empty ("Pick an example or type a program"), compiling, success, warnings, error. Size cap 20,000 chars → friendly message.

**Token Explorer:** table with kind chip (icon + text), text, `line:col`, length; filter by kind; show first 2,000 tokens (notice if more). Rows are `<button>`s with arrow-key navigation. Legend explaining each category in simple language. Clicking a row selects the token.

**AST Explorer:** badge `generated`. Toggle **Graph | Outline**. Graph: React Flow + dagre top-to-bottom, `nodesDraggable={false}`, `nodesConnectable={false}`, `onlyRenderVisibleElements`, zoom/fit controls with `aria-label`s, node click selects, chevron toggles collapse (collapsed `Set<nodeId>` in component state; re-layout on change), "Expand all", "Reset view". Outline: accessible collapsible tree list. Side panel for the selected node: kind, range (line:col–line:col), type, name, child count, plain-language explanation.

**Semantic view:** (a) **Symbol table**: name, kind, type, declared at, use count; row click → `symbol` selection. (b) **Scope tree canvas (`ScopeTreeCanvas`)**: visual React Flow diagram of nested lexical scopes (global, function, block) and their declared symbols. (c) **Diagnostics list** (shared `DiagnosticList`): severity icon + text, code, stage, `line:col`, expandable raw message/notes, a short "Why this error?" from `content/explanations.ts`; click → `diagnostic` selection. Selected expression nodes show their computed type in the explanation panel.

**IR view:** badge `generated`. Row-based read-only view (custom list of `<button>` rows from `IRLine[]`, **not** Monaco) with line numbers and regex syntax colouring (opcodes, `%names`, `@globals`, types, labels, numbers). Row click → `ir` selection. Function selector if several functions. "Copy IR" button. Static note: "LLVM IR is an intermediate language: not C and not machine code. Real LLVM IR for the same program can differ (metadata, attributes, `phi` nodes)." Selected-instruction panel: opcode meaning, the value's type (printed lines leave out types they do not declare, so the panel is where they stay visible), operands (built from the `IRInstr`, not parsed from text), result name, and the source mapping or the `unavailable` reason.

**Assembly view (`AssemblyView`):** badge `illustrative`. Row-based read-only view of lowered x86-64 assembly in Intel syntax. Row click → `asm` selection. Highlights the 1:1 corresponding IR instruction and source range. Includes function breakdown and "Copy Assembly" button.

**Execution view (`ExecView`):** badge `simulated`. Interactive virtual machine stepping through the generated IR. Controls: Step Forward, Step Back, Run, Pause, and Reset. Visualizes the call stack (call frames, slot counts, released frames), 4-byte stack slot allocations, the data segment (globals, including whole arrays), heap blocks with their address range and a *released* marker once freed, everything `print`/`printf` has written at that step, and the return value. Safety bounds: maximum 5,000 steps, 100 call frames and 1,000,000 cells of memory. Runtime faults (null dereference, use-after-free, double free, out-of-bounds index, invalid or unrelated pointer, division/modulo by zero, use-after-return) end the run with an error and the failing instruction selected.

**Shell polish:** Resizable editor and workspace split panes (`ResizablePanes`), global theme switcher (`ThemeToggle` supporting light, dark, sepia, and system), and bottom status bar (`StatusBar`).

**Explanation panel (`ExplanationPanel`)** — four sections: *Simple explanation*, *Technical explanation*, *Why it matters* (static per stage, collapsible) and *Selected item* (dynamic). **All text lives in `content/explanations.ts`**, keyed by stage, `TokenKind`, `AstKind`, `IROpcode` and diagnostic `code`. Introduce terms before using them. Keep text concise.

**Robustness:** an error boundary around each stage workspace; `compile()` never throws; limits: source ≤ 20,000 chars / 800 lines.

**Accessibility basics:** interactive rows/nodes are real buttons (or have `role`, `tabIndex`, `aria-selected`); visible focus rings; contrast ≥ 4.5:1; status shown with icon + text, not colour alone.

## 9. Compile flow
1. User clicks Compile → store sets `status: 'compiling'`, clears stale state.
2. `compile(model.getValue())` → `CompileResult` stored with its `sourceHash`.
3. UI derives stage statuses (`status.ts`), markers, and the first relevant tab (first error's stage, else keep current tab).
4. Editing the source after a compile marks results stale (7.4 #5).

## 10. Examples (`content/examples.ts`)
```ts
interface Example { id: string; title: string; category: 'learn' | 'error'; objective: string;
  code: string; suggestedStage: Stage; explanation: string;
  expected: 'success' | 'warnings' | 'error'; expectedErrorCodes?: string[];
  /** Passes that must visibly change this program when run on their own. */
  demonstrates?: OptPassId[] }
```
Learning examples (22, all valid Mini-C — each must compile with **zero** diagnostics — each focused on one idea): variables and arithmetic; operator precedence (`2 + 3 * 4`); if/else; while loop (sum 1..n); for loop; function with parameters and a call; recursion (factorial); short-circuit `&&`/`||`; local value forwarding; constant folding; branch folding; common subexpression elimination; dead-code elimination; an all-four-passes optimisation tour; globals read and written across a call; scopes and shadowing; `break`/`continue` in a `while` loop; arrays and element access; two-dimensional arrays; pointers, addresses and `malloc`; structs, unions and `->`; recursion with `printf` (the whole `code.c` program).
Error examples (9): missing semicolon (`E2001`), undeclared identifier (`E3001`), wrong argument count (`E3004`), unused variable/missing return warning (`W4001`/`W4002`), unsupported character (`E1010`, the lexer fails and every later stage is blocked), reserved keyword (`E1010`, the parser refuses it), redeclaration in the same scope (`E3002`), a field the record does not declare (`E3005`), passing a record by value (`E1010`).
A test pins the counts (31 = 22 learning + 9 error) and the ids. An example listing `demonstrates` must suggest the Optimization stage, and a test runs each listed pass **in isolation** on that example and fails if it produces no transformation — an example can never advertise a pass it does not actually show. The whole set is also run through **every** combination of the four passes under the interpreter, which must give an identical outcome, identical globals, identical output and no extra steps.
Loading an example shows a small guidance card above the editor (objective, "Try this: open <stage>", explanation) and enables **Reset to example**.

## 12. Pitfall checklist
- ❌ Don't call output "Clang output" or "real LLVM IR".
- ❌ Don't relate stages by text matching — IDs and ranges only.
- ❌ Don't move the Monaco caret from store changes; decorations only.
- ❌ Don't compute highlights for stale results.
- ❌ Don't renumber IR value names; don't use `phi`.
- ❌ Don't render React Flow without an explicit-height parent; don't define `nodeTypes` inside a component.
- ❌ Don't touch `window`/`localStorage` during SSR; don't import Monaco on the server.
- ❌ Don't add libraries, features, or polish beyond this spec; don't build anything from section 13.
- ✅ `compile()` is pure and total; all explanation text in `content/`; engine code testable without React; keep files small and single-purpose.
